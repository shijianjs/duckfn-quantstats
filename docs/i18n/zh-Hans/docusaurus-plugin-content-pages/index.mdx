<dfk-features section-title="这个扩展给了你什么">

<dfk-feature icon="lucide:layout-list" title="整张表，一次调用">
把一张按日期排列的长表交进去，聚合内部按 symbol 分组，所以 SQL 不用写 GROUP BY，一百个标的也还是一条 SELECT。
</dfk-feature>

<dfk-feature icon="lucide:line-chart" title="收益率或价格都行">
qs_html_reports 收周期收益率；qs_html_reports_by_prices 收价格或净值并自己差分，所以 pct_change 那个窗口不必写进 SQL。
</dfk-feature>

<dfk-feature icon="lucide:scale" title="基准就是表里的 symbol">
基准是同一张表里一个普通的 symbol，在配置里指名；它只作输入、自己不出报告。多个基准就是多份报告。
</dfk-feature>

<dfk-feature icon="lucide:folder-output" title="落盘，或者开在浏览器里">
output_dir 把每份报告落到本地目录，文件名由函数生成且永不覆盖；open_in_browser 在文件就位后直接打开。
</dfk-feature>

<dfk-feature icon="lucide:globe" title="任何 DuckDB 客户端都能用">
命令行、Python、Java/JVM、Node、R，或者浏览器里的 DuckDB-Wasm —— 一条 INSTALL 就把同一个签名扩展装到 DuckDB 支持的每个平台，报告到哪都是纯 SQL。不用装 quantstats，也不用维护 Python 环境。
</dfk-feature>

<dfk-feature icon="lucide:life-buoy" title="这份文档站">

## 一条 SQL，一份报告

这就是全部接口：对一张长表做一次聚合调用，不用写分组、也不需要 Python。右边是它给 GOOGL 出的报告（基准是标普 500）—— 真实输出，直接嵌在 iframe 里。

<div className={styles.codeGrid}>

```sql title="duckdb"
-- once per session: INSTALL duckfn_quantstats FROM community; LOAD duckfn_quantstats;
WITH prices AS (
    SELECT *
    FROM read_csv('https://shijianjs.github.io/duckfn-quantstats/demo/prices.csv')
)
SELECT (r).symbol, (r).benchmark, length((r).html) AS html_bytes
FROM (
    SELECT unnest(qs_html_reports_by_prices(
               symbol, date, price,
               {'benchmark': ['SPX'],
                'benchmark_title': ['S&P 500'],
                'title': symbol,
                'strategy_title': symbol}::qs_html_report_options)) AS r
    FROM prices
);
```
